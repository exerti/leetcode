# 智能错题复习系统

## 三张核心表

| 文件 | 位置 | 作用 |
|------|------|------|
| `错题记录.csv` | `.claude/review/` | 每次 fix 的详细错误日志（只增不改） |
| `题目掌握度.csv` | `.claude/review/` | 每道题的掌握程度 + 遗忘曲线（动态更新） |
| `复习题单_{date}.csv` | `{date}/review/` | 当次生成的复习计划（按需生成） |

---

## 第一部分：错误自动记录

### 触发条件（两种模式都要归档）
| 模式 | 触发词 | 说明 |
|------|--------|------|
| **修复模式** | "fix" | 直接改代码，修复完后立即归档 |
| **引导模式** | "引导" / "继续" / "现在呢" / "对了吗" | 用户自己写，你指出错误让他改。错误在会话中累积，当用户说"归档"或切换到新题时一次性写入 |

### 引导模式归档时机
- 错误在会话中**暂存**，不每轮立即写 CSV
- 写入时机：
  1. 用户主动说"归档"
  2. 用户说"继续" + 切换到新题目
  3. 问题解决后，**主动问**"这些错误要归档吗？"
- 一次性将所有累积错误写入 `错题记录.csv` 和 `题目掌握度.csv`

### 执行动作 A — 追加错题记录
每次触发后，将本轮发现的错误追加到 `.claude/review/错题记录.csv`：
```csv
日期,文件名,题目名称,算法类型,错误分类,具体错误,复习状态
```

### 执行动作 B — 更新掌握度
每次 fix 后，**自动降低**该题的掌握程度：
- 如果 `.claude/review/题目掌握度.csv` 中没有该题 → 新增，`掌握程度=1`，`累计错误次数=本次错误数`
- 如果已有 → `掌握程度 = max(1, 当前掌握度 - 1)`，`累计错误次数 += 本次错误数`
- 重新计算 `间隔天数` 和 `下次复习日期`

### 掌握度 & 遗忘曲线表

| 掌握程度 | 间隔天数 | 含义 |
|---------|---------|------|
| 1 | 1 天 | 刚犯错，明天必须重刷 |
| 2 | 3 天 | 回生，短期记忆巩固中 |
| 3 | 7 天 | 基本掌握，一周后检验 |
| 4 | 14 天 | 较熟练，两周后检验 |
| 5 | 30 天 | 已掌握，月度维持 |

### 题目掌握度 CSV 格式
```csv
题目名称,算法类型,累计错误次数,复习次数,上次复习日期,掌握程度(1-5),间隔天数,下次复习日期
```

### 错误分类规范
| 分类 | 说明 | 示例 |
|------|------|------|
| 语法-lambda | Kotlin lambda 语法 | `head->{}` 应为 `{ head -> }` |
| 语法-when | when 表达式语法 | 缺少 `{}` |
| 语法-拼写 | 类名/方法名拼写 | `PorityQueue` → `PriorityQueue` |
| 语法-函数引用 | 函数引用 receiver | 未绑定 vs 绑定引用 |
| 类型-泛型 | 泛型参数错误 | `HashMap<String>` 应为 `HashMap<Char>` |
| 类型-返回 | 返回类型不匹配 | 返回 `List` 非 `IntArray` |
| 逻辑-比较器 | 比较规则错误 | 按值 vs 按频率 |
| 逻辑-遍历对象 | 遍历了错误集合 | 遍历 `nums` 而非 `keys` |
| 逻辑-边界 | 边界条件写反 | `>=right` 应为 `>=left` |
| 逻辑-收缩位置 | left/right 移动错 | `right-1` 应为 `preIndex+1` |
| 逻辑-越界 | 数组越界 | `nums[i-1]` 当 `i=0` |
| 逻辑-死循环 | while 不结束 | peek 不 poll |
| 逻辑-指针 | 指针不前进 | `cur` 不更新 |
| 逻辑-数据错误 | 存了错误值 | 存索引非值 |
| 逻辑-去重 | 去重漏写 | 缺 `i>0` 判断 |
| 逻辑-前置条件 | 缺少必要步骤 | 忘记 `sort()` |
| 逻辑-参数 | 参数使用错误 | target 硬编码 |
| 逻辑-递推公式 | DP 递推公式写错 | `dp[i]` 写成 `dp[i-1]` |
| 逻辑-返回值 | 返回了非全局最优 | 返回 `dp[n-1]` 非全局 max |
| 逻辑-初始化 | 初始值选错 | `maxSum=0` 全负数出错 |
| 逻辑-变量混淆 | 用错变量名 | `maxSum+=` 写成 `sum+=` |
| 类型-初始化 | 初始化为 null 导致类型问题 | `var x = null` 不能用于 `maxOf` |
| 语法-返回 | 缺少 return 语句 | 函数体末尾无 return |

## 第二部分：生成智能复习题单

### 触发条件
"帮我列出复习题单" / "复习计划" / "薄弱题目" / "哪些需要重刷"

### Step 1: 读取数据
- 读取 `.claude/review/错题记录.csv`（错误详情）
- 读取 `.claude/review/题目掌握度.csv`（掌握程度 + 遗忘曲线）
- 当前日期作为 `today`

### Step 2: 智能排序 — 出题优先级算法

```
优先级分值 = (今日到期 ? 100 : 0)       // 遗忘曲线到期，必须刷
           + (6 - 掌握程度) * 15        // 掌握度越低越优先
           + 累计错误次数 * 3           // 历史犯错越多越优先
           + min(距下次复习天数, 10) * 2 // 快到期的不如已到期的，但也提前提醒
```

按分值降序排列，取 TopN（默认全部列出，标注优先级）。

### Step 3: 输出统计 & 题单

#### 统计面板
```
📊 题目总数: N | 需今日复习: X | 三天内到期: Y | 已掌握: Z

🔴 高优先级（今日必刷）：
🥇 三数之和 — 掌握度1 · 4次错误 · 今日到期
...

🟡 中优先级（本周内）：
...

🟢 低优先级（已掌握/未到期）：
...
```

#### 生成 CSV
输出 `复习题单_{date}.csv`：
```csv
优先级,题目名称,算法类型,掌握程度,累计错误,距到期天数,上次失误要点
```

### Step 4: 复习后更新掌握度
用户完成复习后可说 **"已复习 {题目名}"** 或 **"复习完成"**：
- 弹出评分提示：`这道题你觉得自己掌握了吗？(1-5，5=完全掌握)`
- 用户输入评分 q：
  - q >= 4 → 掌握度 +1（上限5）
  - q == 3 → 掌握度不变
  - q <= 2 → 掌握度 -1（下限1）
- 更新 `复习次数 += 1`，`上次复习日期 = today`
- 重新计算 `间隔天数` 和 `下次复习日期`

## 第三部分：创建重刷骨架文件

### 触发条件
生成复习题单后自动执行。

### 规则
- 按优先级从高到低，在 `{date}/review/redo/` 下创建骨架（平铺，不分算法子目录）
- 如果文件已存在 → **跳过**（保护用户已写的代码）
- 每个文件顶部注释标注上次失误
- ⚠️ **类名必须唯一**：`class Solution` 会导致同包名下的 Redeclaration 冲突
  - 命名规则：`{算法缩写}{题目简述}`，如 `DpMaxSubArray`、`HeapTopKFreq`、`ThreeSum`
  - package 保持不变（`package review` 或 `package review.redo`），通过类名区分

### 模板
```kotlin
package review.redo

/**
 * ⚠️ 上次失误（来自错题记录）：
 * 1. xxx
 * 2. xxx
 * 📈 掌握度: 1/5 | 累计错误: 4次 | 间隔: 1天
 */
class DpMaxSubArray {  // ← 唯一类名，非 Solution
    fun xxx(): ReturnType {
        TODO()
    }
}

fun main() {
    val handler = DpMaxSubArray()::xxx  // ← 引用需同步更新
}
```

### 完成后提示
"骨架已按优先级生成，从上到下刷即可。刷完后说「已复习 {题目}」，我会更新掌握度。"
